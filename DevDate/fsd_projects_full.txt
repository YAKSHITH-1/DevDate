Project Feed & Tinder-Style Interaction The feed is a list of eligible OPEN projects. Cards show image, title, member count, skills, required roles, category, and compatibility score. The UI supports both gestures and explicit buttons so the feature remains demo-friendly. Eligibility excludes: projects owned by the current user, projects already passed/interested by the current user, closed projects, and projects at capacity when no further applicants are useful. If the owner later accepts, the server creates a match and membership atomically where practical. 9. Compatibility / Matching Engine The matching algorithm is deterministic and intentionally simple. This is a functional rule, not a machine-learning model. Skill component   = matched required skills / total required skills Interest component = matched project interests / total project interests (if project interests are modeled; otherwise use category/interest tags) Role component     = 1 when user role is in project.requiredRoles, else 0 Final score        = 0.50 * skillComponent + 0.30 * interestComponent + 0.20 * roleComponent Display percentage = round(Final score * 100) Recommended implementation detail: store project.skills as the required technical skill set and project.category as the interest/category proxy. For stricter adherence to the stated product model, add project.interests as an optional array; when present, use it for the 30% component.
